SLIDE 01
Why This System

Problem Statement

Before GATEE Portal, FLN tracking across VJNT schools was manual, inconsistent, and inaccessible to higher authorities.

  • ❌
    No centralised data — each school maintained paper registers, making district/division-level review impossible.
  • ❌
    No phase tracking — it was unclear which schools had completed FLN assessments for which phases.
  • ❌
    No approval workflow — data submitted by schools had no verification or sign-off mechanism.
  • ❌
    No student reports — generating individual student progress reports required manual effort.
  • ❌
    No year-end process — class promotion and graduation of Class IX students had no digital record.

GATEE Portal Solves

  • ✅ Centralised, real-time student FLN data
  • ✅ 4-phase structured assessment per year
  • ✅ Head Master approval workflow per phase
  • ✅ Auto-generated PDF student report cards
  • ✅ Automated class promotion with full audit trail
  • ✅ Analytics dashboards at every level
  • ✅ Parent meeting (Palak Melava) tracking

SLIDE 04
Core Workflow

FLN Phase Assessment Workflow

Every academic year has 4 phases. Each phase must be completed and approved before the next phase unlocks.

📘 Phase 1

Baseline assessment. Seeded from last year's Phase 4 data after class promotion. School Coordinator enters current Marathi, Math, English levels for every student.

📗 Phase 2

Mid-year assessment 1. Unlocks only after Phase 1 is approved by Head Master. Coordinator updates student levels.

📙 Phase 3

Mid-year assessment 2. Unlocks after Phase 2 approval. Progress is measured against Phase 1 baseline — "level jumps" tracked.

📕 Phase 4

Year-end final assessment. After approval, this data becomes the seed for next year's Phase 1 via class promotion.

SLIDE 06
Key Feature

Year-End Class Promotion System

A fully atomic, audited, 6-step transaction that promotes all students at year-end — with Class IX graduating permanently.

6-Step Promotion Transaction

  • 1
    Create promotion log — records who promoted, when, and for which academic year.
  • 2
    Archive all phase data → student_phase_history table. Complete audit trail preserved.
  • 3
    Archive & clear phase approvals — approval records saved to history, then cleared for new year.
  • 4
    Graduate Class IX — moved to graduated_students table permanently, marked inactive.
  • 5
    Promote Classes I–VIII — advance class, seed Phase 1 from last completed phase (COALESCE).
  • 6
    Update log counts — records total promoted and graduated counts for audit reference.

🔒 Smart Phase Seeding (COALESCE)

Phase 1 for new year is seeded from the best available phase:

Phase 4 → Phase 3 → Phase 2 → Phase 1

Schools that didn't complete all 4 phases still get a meaningful baseline for the new year.

📋 4 Audit Tables

  • class_promotion_log — one row per promotion run
  • student_phase_history — all student phase data
  • graduated_students — permanent IX graduate record
  • phase_approvals_history — approval decisions archive

SLIDE 09
Security & Access

Security Features

🔐 Authentication

  • BCrypt password hashing
  • Account lockout after failed attempts
  • Session-based login management
  • Secure logout — session invalidation
  • Change password with verification

🛡️ Authorisation

  • Every JSP checks session + role
  • Every servlet validates user type
  • DATA_ADMIN-only pages redirect on unauthorised access
  • School coordinators limited to own UDISE
  • Officers limited to their geography

🖼️ Media Security

  • Palak Melava photos encrypted at rest
  • Images served via SecureImageServlet
  • Videos stored on BunnyCDN (private)
  • YouTube upload with OAuth 2.0
  • No direct file-path exposure

📋 Data Integrity

  • Phase locking — next phase disabled until previous is approved
  • All promotions are atomic DB transactions (rollback on any error)
  • Full audit trail — nothing is deleted, everything archived
  • Graduated students permanently preserved in separate table

🔒 Input Validation

  • Type-to-confirm (PROMOTE) for destructive operations
  • Academic year validation before promotion
  • SQL injection prevention via PreparedStatement throughout
  • Server-side role checks (not just client-side)
