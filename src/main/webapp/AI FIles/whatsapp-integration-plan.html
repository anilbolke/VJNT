🎯 1. Objective

Send automated WhatsApp notifications to school coordinators, Head Masters, division officers, and DATA_ADMIN at key events in the FLN assessment lifecycle — phase submissions, approvals, class promotions, reminders, and more — using pre-approved message templates.

Phone numbers are already present in the database:

  • school_contacts.whatsapp_number / mobile — school coordinator & Head Master contacts per UDISE
  • teachers.mobile_number — teacher contacts
  • users.mobile — system user contacts (DATA_ADMIN, officers)

🔄 5. Message Send Flow

1
Event fires in servlet e.g. Head Master approves Phase 1 → approval servlet calls WhatsAppService.send()
2
WhatsAppService looks up recipient number Queries school_contacts table for whatsapp_number by udise_no and contact_type
3
Build template payload Maps event data to template variables (school_name, phase_number, coordinator_name, etc.)
4
HTTP POST to MSG91 API Sends JSON payload with template name, recipient number, and variable values
5
Log result to whatsapp_message_log Stores message ID, recipient, template, status (SENT/FAILED), timestamp — always logged even on failure
6
Admin can view logs from dashboard New "WhatsApp Logs" card in DATA_ADMIN dashboard shows delivery status per message

🗄️ 6. Database Tables to Create

whatsapp_config

CREATE TABLE whatsapp_config ( config_id INT NOT NULL AUTO_INCREMENT, config_key VARCHAR(100) NOT NULL UNIQUE, -- 'api_key','sender_id','base_url','enabled' config_value TEXT, updated_by VARCHAR(100), updated_date DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP, PRIMARY KEY (config_id) ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

whatsapp_templates

CREATE TABLE whatsapp_templates ( template_id INT NOT NULL AUTO_INCREMENT, template_key VARCHAR(100) NOT NULL UNIQUE, -- internal key e.g. 'PHASE_APPROVED' template_name VARCHAR(100) NOT NULL, -- MSG91 approved template name description VARCHAR(255), is_active TINYINT(1) DEFAULT 1, PRIMARY KEY (template_id) ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

whatsapp_message_log

CREATE TABLE whatsapp_message_log ( log_id BIGINT NOT NULL AUTO_INCREMENT, template_key VARCHAR(100), -- e.g. 'PHASE_APPROVED' recipient_no VARCHAR(15) NOT NULL, udise_no VARCHAR(20), event_ref VARCHAR(200), -- e.g. 'promotion_id=3' or 'phase=2,udise=123' variables_json TEXT, -- JSON of template variables used status ENUM('SENT','FAILED','PENDING') DEFAULT 'PENDING', provider_msg_id VARCHAR(100), -- MSG91 message ID for delivery tracking error_message TEXT, sent_at DATETIME DEFAULT CURRENT_TIMESTAMP, PRIMARY KEY (log_id), INDEX idx_wml_udise (udise_no), INDEX idx_wml_status (status), INDEX idx_wml_sent_at (sent_at) ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

🌐 9. MSG91 API Integration Detail

Endpoint

POST https://api.msg91.com/api/v5/whatsapp/whatsapp-outbound-message/bulk/

Request JSON (per message)

{ "integrated_number": "91XXXXXXXXXX", // your MSG91 WhatsApp sender number "content_type": "template", "payload": { "to": [{ "user_property_1": "91<recipient_number>" }], "type": "template", "template": { "name": "gatee_phase_approved", // pre-approved template name "language": { "code": "mr" }, // mr = Marathi, en = English "components": [ { "type": "body", "parameters": [ { "type": "text", "text": "Coordinator Name" }, { "type": "text", "text": "School Name" }, { "type": "text", "text": "2" }, { "type": "text", "text": "3" } ] } ] } } }

Authentication

Add header: authkey: <YOUR_MSG91_AUTH_KEY> — stored in whatsapp_config table (not hardcoded).

⚠️ 12. Important Considerations

  • Template approval required — all 5 templates must be approved by Meta via MSG91 before going live. This takes 1–3 business days.
  • WhatsApp number format — always send with country code: 91XXXXXXXXXX (no +, no spaces). Validate on insert.
  • Recipient must have WhatsApp — use whatsapp_number column if present, fall back to mobile. If neither, skip send, log as SKIPPED.
  • 24-hour rule — WhatsApp only allows template messages for outbound. User-initiated conversations are free for 24 hours. Templates are always charged.
  • Send asynchronously — never call WhatsAppService synchronously inside a DB transaction. Call after conn.commit() to avoid holding transactions open during HTTP calls.
  • Never block on failure — if WhatsApp send fails, log the error but do not rollback the main operation (phase approval / promotion must succeed regardless).
  • API key security — store in whatsapp_config DB table, NOT in source code or property files that go into the WAR.
